# Support Triage & Assist — AI/ML-система обработки тикетов поддержки

Проектное решение + минимальный работающий PoC для автоматизации обработки
тикетов поддержки крупного онлайн-сервиса (~200k тикетов/день, всплески до
10–20k за 10 минут во время инцидентов).

Ключевая идея: **разделить быстрый путь и медленный путь**. Классификация и
маршрутизация («горячий» путь, цель < 500 мс) отделены от генерации ответа
(асинхронный путь). Рискованные категории и низкая уверенность всегда уходят
человеку; безопасные типовые обращения могут закрываться автоматически.

## Что здесь реальная реализация, а что — дизайн

| Часть | Статус в PoC |
|---|---|
| Оркестрация конвейера, маршрутизация, политика эскалации | **реализовано** |
| PII-редактирование, детекция prompt injection, аудит-лог | **реализовано** |
| Retrieval по базе знаний | реализовано на TF-IDF как **stand-in** для эмбеддингов |
| Классификатор темы + уверенность | реализован **baseline** на ключевых словах |
| Генерация черновика (LLM) | **мок** (сборка из KB); реальный LLM за флагом, выключен |
| Векторная БД, очередь, эмбеддинг-модель, дообученный классификатор | **дизайн** (docs/) |

Что является упрощением и как заменяется в целевой архитектуре — подписано
в коде и в `docs/architecture.md` / `docs/ml.md`.

## Как запустить PoC

Зависимостей нет — только стандартная библиотека Python 3.8+.

```bash
python demo.py                      # end-to-end: happy path + fallback/risky path
python -m unittest discover tests   # smoke-тест (6 инвариантов)
```

Опционально в контейнере:

```bash
docker build -t support-triage . && docker run --rm support-triage
```

## Какой сценарий демонстрируется

`demo.py` прогоняет 7 мок-тикетов через все 6 шагов сценария из ТЗ:
приём → определение темы и риска → поиск в базе знаний → черновик ответа
или маршрут → запись лога решения → **эскалация рискованного/low-confidence
случая оператору вместо автозакрытия**. Отдельно показывается корректная
деградация при недоступности LLM (даже безопасный FAQ уходит оператору).

Наблюдаемые исходы демо:

- **🟢 Автозакрытие** — типовой FAQ (сброс пароля, где скачать счёт): безопасная
  категория, высокая уверенность, есть опора в KB.
- **🟡 Черновик оператору (suggest)** — тема понятна, но не в allowlist
  автозакрытия (сбой приложения).
- **🔴 Эскалация оператору** — возврат денег (+ отредактированная PII-карта),
  prompt injection, удаление данных по GDPR, непонятный тикет.

## Ключевые допущения и ограничения

- Данные — маленький синтетический датасет; **модели не обучались** (это не цель).
- TF-IDF не сшивает языки — в PoC компенсируется многоязычными тегами в KB;
  в целевой системе это решают многоязычные эмбеддинги.
- Уверенность классификатора — эвристика; в целевой системе — калиброванные
  вероятности с порогом abstain.
- Пороги, allowlist безопасных тем и список рискованных категорий — в
  `poc/config.py`.

## Зачем это бизнесу (продуктовая часть)

Поддержка платит ≈150 ₽ за ручную обработку каждого из ~200k тикетов/день, при
этом ~40% потока — типовые повторяющиеся обращения. Система снимает с операторов
рутину (черновики, суммаризация, маршрутизация) и закрывает безопасную часть
типовых обращений без человека — это ускоряет первый ответ (целевой SLA 15 минут),
удерживает CSAT и режет стоимость обработки. Экономический потолок MVP при
консервативной автоматизации 20% потока — порядка **2 млрд ₽/год** валовой
экономии при стоимости LLM-инференса менее 3% от этой суммы (расчёт и
чувствительность к reopen rate — в `docs/product.md`). Главная ценность —
не «закрыть всё», а закрывать безопасное быстро и дёшево, не роняя качество и
не отправляя пользователю непроверенный ответ.
