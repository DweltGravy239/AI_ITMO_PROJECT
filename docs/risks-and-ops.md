# risks-and-ops.md

Коротко, по ключевым пунктам на каждое направление.

## Highload и надёжность

- **Синхронно vs асинхронно:** классификация/маршрутизация — синхронно, бюджет
  < 500 мс, без LLM; генерация — асинхронно из очереди. Медленный путь не
  блокирует быстрый.
- **Пики и очереди:** всплески 10–20k/10 мин поглощаются брокером и деградацией
  качества сервиса; при переполнении — приоритезация рискованных, генерация на
  паузу, дедупликация одинаковых обращений в инциденте.
- **Поведение при недоступности LLM:** горячий путь не зависит от LLM →
  маршрутизация и SLA сохраняются; холодный путь откатывается на retrieval-only
  + маршрут оператору, автозакрытие отключается.
- **Разделение путей:** быстрый путь классификации и медленный путь генерации
  масштабируются и падают независимо; таймауты, ретраи с backoff, circuit breaker
  на внешние вызовы.

## Privacy, safety и risk

- **PII и внешний LLM:** сырые персональные данные (карты, e-mail, телефоны,
  паспорта) редактируются на горячем пути **до** любого внешнего вызова и **не
  попадают в логи**; во внешний LLM API уходит только очищенный текст.
- **Что нельзя закрывать автоматически:** возвраты/платежи, удаление аккаунта,
  запросы персональных данных, безопасность/фрод, жалобы и юридические обращения —
  всегда human-in-the-loop, независимо от уверенности модели.
- **Защита от prompt injection:** пользовательский ввод изолирован от инструкции
  LLM; отдельная детекция инъекций; при срабатывании — эскалация, а не выполнение;
  groundedness-проверка выхода перед отправкой.
- **Аудит автоматических решений:** каждое решение (тема, риск, уверенность,
  действие, причина, использованные фрагменты KB, отредактированный ввод)
  пишется в append-only лог — для разбора инцидентов и обучения.
