# ml.md — ML/LLM-задачи и обоснование подхода

Принцип: **самый простой инструмент, который решает задачу с нужной надёжностью.**
Правила → классический ML → retrieval → LLM, по нарастанию сложности и стоимости.

## Что чем решается и почему

| Задача | Подход | Почему |
|---|---|---|
| PII-детекция и редактирование | **правила (regex) + NER** | должно быть детерминированным и быстрым, до любого внешнего вызова |
| Дедупликация в инцидентах | **хеш + near-dup по эмбеддингам** | дёшево схлопывает одинаковые обращения |
| Жёсткие рисковые триггеры (платёж, удаление, юр.) | **правила/словарь** | требования безопасности не должны зависеть от вероятностной модели |
| Классификация темы | **классический ML** (baseline → трансформер) | горячий путь, нужен предсказуемый latency < 500 мс и калиброванная уверенность |
| Оценка риска категории | **классификатор + правила поверх** | recall рискованного класса важнее precision |
| Поиск ответа/похожих тикетов | **эмбеддинги + retrieval** | семантическое совпадение поверх разных формулировок и языков |
| Черновик ответа, суммаризация | **LLM (RAG)** | генеративная задача с опорой на найденный контекст |

**Где LLM использовать НЕ стоит:** на горячем пути (классификация/маршрутизация —
слишком медленно и дорого на 200k/день), в решении о риске/эскалации (должно быть
детерминированным и аудируемым), в PII-решениях. LLM — только асинхронная
генерация с обязательным grounding и проверками на выходе.

## Baseline, которые разумно запустить первыми

- **Тема:** TF-IDF + линейная модель (LogReg/LinearSVC). Метрика — macro-F1
  (классы несбалансированы). Это дешёвый честный ориентир; сложную модель
  включаем, только если baseline не дотягивает.
- **Риск:** правила + калиброванный бинарный/мультиклассовый классификатор;
  порог настраивается на **recall рискованного класса ≥ 0.95** (пропуск дороже
  ложной эскалации).
- **Retrieval:** BM25 как baseline → плотные эмбеддинги. Метрики — recall@k, MRR.
- **Генерация:** оценивается по acceptance оператором и edit distance до
  финального ответа, плюс groundedness.

## Откуда берутся модели и какие данные нужны

- **Классификатор темы/риска:** дообучаем **внутри** на исторических тикетах
  (открытая многоязычная база вроде ruBERT/ruRoBERTa или многоязычного
  DistilBERT как основа). Данные: тексты тикетов + метки темы/исхода. Технические
  метрики выбора: macro-F1, per-class recall (особенно рискованный класс),
  калибровка (ECE), latency и размер (влияет на бюджет < 500 мс).
- **Эмбеддинги:** **открытая** многоязычная sentence-модель (семейства e5/LaBSE),
  без дообучения на старте; при необходимости — дообучение на парах
  «обращение → решившая статья». Метрики: recall@k, MRR на размеченных парах.
- **Генерация:** внешний LLM API (или self-hosted открытая модель). Выбор по
  acceptance/edit distance и стоимости на объём; предпочтителен более дешёвый
  вариант при сопоставимом качестве.

## Валидация качества

- **Офлайн:** размеченный holdout; для классификации — macro-F1, матрица ошибок,
  per-class recall с отдельным вниманием к рискованному классу; калибровка.
  Для retrieval — recall@k/MRR. Для генерации — acceptance/edit distance на
  выборке решённых тикетов + проверка groundedness.
- **Онлайн:** shadow-режим (предсказания без влияния) → A/B на подгруппе → полная
  раскатка по этапам (см. `docs/product.md`). На проде — выборочная ручная
  разметка потока для оценки реальной точности (см. `docs/monitoring.md`).

## Как обрабатывать низкую уверенность

- **Abstain-порог:** ниже порога уверенности — не автоотвечаем, маршрутизируем
  оператору. Порог калибруется на валидации (баланс автоматизации и ошибок).
- **Рискованная категория** — всегда human-in-the-loop, независимо от уверенности.
- **Groundedness-проверка** выхода LLM: ответ должен опираться на найденный
  фрагмент KB (проверка цитируемости/перекрытия). Не опирается — не автоотправляем.
- **Автозакрытие** только при: тема ∈ allowlist безопасных **И** уверенность выше
  порога автозакрытия **И** риск низкий **И** есть опора в KB **И** прошли
  safety-проверки. Иначе — suggest или эскалация.

## Разметка исторических данных

- **Бутстрап слабых меток** из истории: категория закрытия, применённые макросы,
  теги — как предварительные метки темы; исходы (reopen/CSAT) — как сигнал
  качества.
- **Active learning:** в первую очередь размечаем неуверенные и приграничные
  случаи — там разметка даёт максимум пользы.
- **Золотой набор:** небольшой экспертно размеченный сет для честной офлайн-оценки
  и калибровки порогов.

## Что из этого — упрощение в PoC и как заменяется

| В PoC (упрощение) | В целевой системе |
|---|---|
| Классификатор темы на ключевых словах (`classify.py`) | дообученный многоязычный трансформер с калиброванной уверенностью |
| Уверенность — эвристика (сатурация от числа совпадений) | калиброванные вероятности + abstain-порог |
| Retrieval — TF-IDF + косинус (`retrieve.py`), кросс-язычность через теги в KB | плотные многоязычные эмбеддинги в векторной БД (кросс-язычность из коробки) |
| Генерация — мок из KB (`generate.py`) | RAG-вызов LLM с grounding и изоляцией пользовательского ввода от инструкции |
| PII — только regex (`normalize.py`) | regex + NER-модель |
