# WORKLOG.md — распоряжение тайм-боксом (4 часа)

План на старте: ~30 мин на разбор ТЗ и архитектурное решение (горячий/холодный
путь), ~90 мин на PoC с обоими путями и smoke-тестом, ~90 мин на документацию
для двух программ, ~30 мин на вычитку, сборку и историю коммитов. Приоритет —
сначала работающий скелет happy + fallback путей, потом обвязка и тексты.

Что пошло не по плану: кросс-язычный retrieval на TF-IDF ломал happy-path для
англоязычного тикета — потратил лишнее время на диагностику и решил это
многоязычными тегами в KB, зафиксировав ограничение в документации вместо того,
чтобы тянуть настоящую эмбеддинг-модель. Балансировку порогов уверенности и
allowlist свёл к минимальной, достаточной для демонстрации инвариантов.

Что сознательно вырезал из скоупа и почему (это не production-система за 4 часа):
обучение реальных моделей и разметку большого датасета (не цель задания);
настоящую векторную БД, брокер очередей и эмбеддинг-модель (заменены in-memory
TF-IDF и мок-LLM с явной пометкой, как заменяются); реальную интеграцию LLM API
(оставлена заглушка за флагом, чтобы PoC работал офлайн без ключей); детальный UI
оператора и полноценную MLOps-инфраструктуру (Kubernetes/feature store — прямо
исключены ТЗ). Docker оставил минимальным, основной путь запуска — локальный
`python demo.py`.

WORKLOG сходится с историей коммитов: сначала PoC-модули и данные, затем правка
кросс-язычного retrieval, затем документация и мета-файлы.
